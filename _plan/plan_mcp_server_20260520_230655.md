# MCP Server Plan — locate_tenant

## Context

The project already has all dependencies installed (`mcp 1.27.1`, `sqlalchemy`, `pymysql`, `pyyaml` via `uv`/`.venv`). Core logic is complete across three files but `server.py` (the MCP entry point) does not exist. `main.py` is a placeholder stub. Goal: expose `Tenant.find_by_host_name()` as an MCP tool named `locate_tenant`.

| `server.py` | **Created** — FastMCP server entry point |

| `_plan/plan_mcp_server_20260520_230655.md` | **Created** — this file |

Files **left untouched**: `tenant.py`, `config.py`, `tunnel.py`, `config.yaml`.

## Key Decisions

- **Sync tool** — underlying code uses blocking `time.sleep` + SQLAlchemy; no benefit wrapping in async
- **Strip credentials from output** — `_dataclass_to_dict` deliberately omits `username`/`password` from returned dicts
- **Config loaded per call** — keeps the tool stateless; config file is small so overhead is negligible
- **`Path(__file__).parent`** — makes `config.yaml` path robust regardless of working directory

## Commands

```bash
# Dev mode (inspectable in MCP inspector)
uv run mcp dev server.py

# Install into Claude Desktop
uv run mcp install server.py --name "locate-tenant"

# Test the tool directly
uv run python -c "from server import locate_tenant; print(locate_tenant('amp'))"
```

## Verification Checklist

1. `uv run mcp dev server.py` — MCP Inspector shows one tool: `locate_tenant` with annotated `host_name` parameter
2. Call tool with a known partial hostname → results include `database_server_url` and `schema_name`
3. No credentials (`username`, `password`) in returned dicts
4. Unknown hostname returns `[]`
5. Region connection failure is handled gracefully (existing `Tenant.find_by_host_name` catches per-region exceptions)
